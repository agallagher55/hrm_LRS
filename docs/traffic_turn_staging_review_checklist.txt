TRNLRS_traffic_turn_staging -- Review Checklist
============================================

Purpose
-------
scripts/05_rebuild_traffic_turns.py produced a staging feature class,
SDEADM.TRNLRS_traffic_turn_staging, by spatially remapping turn edge references
from the old edge source (TRN_street) to the new one (TRNLRS_TRN_STREET).
AUTO_SWAP_AND_REBUILD was False, so nothing in production has changed yet --
the current TRNLRS_traffic_turn and TRNLRS_street_network are untouched.

This review exists because the remap is a best-effort spatial match, not a
guaranteed 1:1 translation. Two things can go wrong silently:
  1. A turn gets mapped to the WRONG edge at a multi-leg intersection
     (the angle-based tiebreaker in find_new_oid() is a heuristic).
  2. A turn gets dropped (skipped) that shouldn't have been, or one that
     should have been dropped (e.g. references a removed segment) wasn't.

Once you swap TRNLRS_traffic_turn_staging into place, the old FC is deleted and
the network dataset is rebuilt -- there is no cheap "undo" (see
docs/network_traffic_turns.md, controller-dataset locking). Review now,
before that point.

2. Schema / field check
--------------------------------------------------------------------------
- Fields match the template (Edge1FCID/FID/Pos ... up to the max edge slot
  detected, NODE_ if present) -- compare against TRNLRS_traffic_turn's
  current schema.
- Spot check a handful of records: Edge1FCID should equal the DSID logged
  during the run ("TRNLRS_TRN_STREET DSID: <n>"), which is the edge FC's real
  dataset ID. A value of 2 is the 2026-07-21 bug (that is the edge source's
  ordering index within the network, not its dataset ID) and means the FC is
  broken. Nulls in Edge1FID are also a bug.
- Confirm Edge{N}Pos is 0.5 on every resolved slot. Pos is NOT carried over
  from the old records any more: it identifies which edge ELEMENT of the
  feature the turn uses, and under endpoint connectivity each new edge
  feature is a single element whose canonical position is 0.5. The old
  value referred to a different feature.
- New in this run: read the two "Edge1Pos / Edge1End distribution" lines the
  script logs at startup, and the "Edge1End integrity check" line near the
  end. Agreement below 95% means the geometric junction detection disagrees
  with the source's own Edge1End values -- stop and investigate rather than
  swapping.
- New in this run: the skip summary is broken out by reason
  (too_few_edges / missing_old_geometry / no_shared_endpoint /
  unresolved_edge / new_edge_not_spanning / edge1end_undetermined). Read the
  breakdown, not just the total -- new_edge_not_spanning in particular means
  LRS resegmentation split a middle edge and the turn genuinely cannot be
  represented, which is different from a tolerance problem.
